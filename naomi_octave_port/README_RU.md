# NAOMi для GNU Octave на этом компьютере

Рабочая копия: `C:\Users\User\NAOMi_octave`.
Octave: `C:\Octave`, версия 11.3.0, Windows x64.
Исходная папка `C:\Users\User\NAOMi` сохранена отдельно.

Проверенный результат: `results\demo_15hz_seed1` — 300 кадров 70 x 70,
15 Гц, 20 секунд, 12 клеток в ткани, 2357 событий. На изображении видна
только часть клеток объёма. Проверены все 300 TIFF-страниц независимым
чтением Pillow, число кадров и частота AVI через FFprobe, а массивы и
квантование TIFF — из Octave. Отчёты: `validation.json` и
`export_validation.json`, диагностический рисунок — `verification.png`.

## Запуск

Открой `C:\Users\User\NAOMi_octave\START_NAOMi.cmd` двойным щелчком.
Программа рассчитает небольшой пример и напечатает папку результата.
Первый расчёт включает построение ткани и распространение света; он заметно
дольше расчёта нескольких кальциевых кривых. Окно во время расчёта не закрывай.

Из командного окна Octave:

```matlab
cd('C:/Users/User/NAOMi_octave/code')
clear functions
run_naomi_octave
```

По умолчанию: 12 запрошенных клеток в ткани 80 x 80 x 50 мкм, GCaMP6s,
ядерная флуоресценция, 15 кадров/с, 300 кадров (20 секунд), без движения.
Глубина 50 мкм. Оптика рассчитывается исходной моделью распространения света
NAOMi по согласованной с объёмом сетке 40 мкм, без дополнительного плотного
уточнения маски. Внутренняя сетка ткани 0.5 мкм; выходной пиксель при штатном
биннинге 1 мкм. Число видимых клеток может быть меньше числа клеток в ткани.

Другие длина и seed:

```matlab
run_naomi_octave(struct('n_frames',1000,'seed',2))
```

Здесь нет анатомической или шумовой калибровки по реальной рыбе. Это рабочий
синтетический ядерный двухфотонный baseline. Light-sheet ZAPBench требует
другой оптической модели. Фоновые аксоны и сосуды в этом примере отключены.
Остальные старые авторские сценарии, GUI, Bessel/vTwins и low-RAM режимы
не входят в проверенный маршрут запуска.

## Результаты

Каждый новый запуск создаёт собственную подпапку `results`:

- `simulation_result.mat`: точные float-массивы `Fsim`, `Fsim_clean`, сигналы
  `activity`, события на 100 Гц, геометрия `vol`, PSF, параметры и временная сетка.
- `activity_noisy.tif`, `activity_clean.tif`: многостраничные uint16 TIFF.
- `activity_noisy.avi`: видео для просмотра.
- `preview.png`: максимальная проекция чистой записи по времени.
- `metadata.json`, `run.log`: параметры, длительности этапов и журнал.
- `anatomy_checkpoint.mat`, `optics_checkpoint.mat`: промежуточные результаты.

TIFF используют один общий масштаб для всей пары видео и всего времени.
Восстановление интенсивности: `double(TIFF) / tiff_scale + tiff_offset`.
Точные значения до квантования всегда находятся в MAT. Нормирования каждого
кадра по отдельности нет.

Последняя команда проверяет формы и конечность массивов, реальные события,

## Что исправлено

- MEX пересобраны для Octave; исправлены типизированные указатели `mxGetData`,
  стандартные C++-заголовки и ошибки вспомогательной функции соседей.
- `installNAOMi` определяет готовность MEX по активной среде.
- `cscvn`/`fnval`: совместимость для используемых NAOMi pp-сплайнов через
  бесплатный пакет Octave `splines`; это не реализация всего MATLAB Toolbox.
- Вокселизация вычисляет пересечения один раз для одинаковых x/y лучей.
  Исходная функция сохранена для сравнительного теста; правила границ сохранены.
- Обе функции пространственных Gaussian processes используют заданный seed,
  без неподдерживаемого `simdTwister` и без переинициализации по часам.
- Исправлены ветка Hawkes в `generateTimeTraces`, точная рациональная
  передискретизация (включая 15 Гц) и сохранение требуемого числа кадров.
- Перестройка small-world графа корректно обрабатывает маленькие сцены,
  когда свободных соседей меньше, чем запрошенных замен связей.
- В сканере исправлено вычитание ядерного baseline; отдельный тест проверяет
  сохранение заданных амплитуд флуоресценции 2:3:2.
- `single_scan` работает без осевого биннинга и не требует MATLAB-флага
  `ifft(...,'symmetric')`.
- Сетка оптического распространения согласуется с размером ткани: для
  поля 80 мкм используются позиции 0, 40, 80 вместо выхода за край на 100 мкм.
- Новый сценарий сохраняет MAT v7, TIFF и AVI без `matfile` и MATLAB `Tiff`.
- Все TIFF-страницы записываются одним вызовом как grayscale uint16:
  это обходит перевод последующих страниц в RGB16 при GraphicsMagick Append.

MEX-функции `array_*` намеренно меняют входные массивы на месте, как в NAOMi.
Их не следует использовать как обычные функции с безопасными копиями массивов.

## Воспроизводимость и обслуживание

Пакеты этой установки: image 2.20.0, statistics 1.8.3, signal 1.4.7,
splines 1.3.5, video 2.1.3. В симуляции используется twister с заданным seed.
Побитовая идентичность с MATLAB не заявляется.

Вызов `naomi_octave_setup(true)` пересобирает MEX после смены версии Octave.
Для переноса на другой компьютер нужны полный репозиторий NAOMi, файлы порта,
пакеты и пересборка MEX. Скрипт `patch_naomi.ps1` в папке проекта воспроизводит
изменения. Исходные версии изменённых файлов лежат в `octave_port_upstream`.

Параметр `resume=true` предназначен для продолжения прерванного расчёта с
явно указанным `run_name`. После изменения анатомии или оптического кода
нужно использовать новый `run_name`, чтобы не загружать старые checkpoints.
